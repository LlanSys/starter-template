# Defects found during real operator acceptance

These defects were found using real local Docker accounts and normal password/MFA sessions. They are retained here so a later passing run does not hide what failed initially.

| Defect | Reproduction and cause | Correction | Verification |
| --- | --- | --- | --- |
| QA-01 | Bulk operator MFA setup could wait behind the same anonymous IP budget. Rate limiting ran before authentication and queued authenticator requests for a five-minute window. | Authenticate before limiting; use validated workspace/user budgets for authenticated authenticator operations, preserve anonymous IP budgets, return immediate 429/Retry-After. | Real two-user JWT regression and completed local operator enrollments. |
| QA-02 | A customer's protected administrator could not delegate supported tenant-settings permissions; four shipped endpoint keys were missing from the vendor permission seed/default role. | Add four definitions and conservative vendor-managed Tenant Administrator upgrades for SQL Server and PostgreSQL IAM/ControlPlane. Preserve copied/custom roles. | Provider/onboarding tests and both live customer role-delegation runs passed. |
| QA-03 | A correctly tenant-scoped setting write was followed by a cache-miss read using the platform tenant. Queued HybridCache factories lost ambient request context. The direct cache read was also a stub. | Preserve ExecutionContext and scoped lifetime; implement direct reads; tenant mutation epochs, shared epoch reads and request-v2 result namespace. | Three original regressions failed before and passed after the fix; five expanded cache tests passed, including real two-tenant HTTP reads and a platform decoy. Final Docker two-customer settings read/write/deletion isolation passed. |
| QA-04 | A staff dialog disappeared during routine session refresh even when effective authority was unchanged. | Compare identity/session/MFA/proxy/permission state before clearing obsolete UI. Preserve open forms on unchanged authority; cancel on actual access change. | Final Docker browser check passed: entered name and collector preset remained for 353 seconds across routine session refresh; probe cancelled without saving. |
| QA-05 | The limited customer coordinator saw Navigation/Access Catalog links and IAM tabs it could not use. API operation permissions still denied access. | Shared operation floors for shipped admin navigation and native route policies; permission-filtered IAM tabs, action buttons and read-only row controls; omit unavailable permission claims. | Unit and real-session navigation tests passed; browser revocation removed user results and tabs on the next protected read, and grants were restored. |

| QA-06 | A suspended customer returned HTTP 500 in Development. | Use the sanitized API exception handler in every environment; preserve KYC in lifecycle responses and require fresh MFA after reactivation. | Real two-customer Docker suspension/reactivation passed; problem-contract and real-session regressions passed. |
| QA-07 | An internal support proxy appeared as an active ordinary person. | Ordinary people queries and administration/invitation/credential handlers accept Human identities. Support and Demo keep their dedicated entry/expiry/revocation workflow. | Real support/onboarding regression and final Docker proxy-list/mutation checks passed. |
| QA-08 | An intermediate UI change filtered explicit platform grants using tenant-module unavailability. | Shared CurrentUserPermissions projection preserves supported explicit staff grants, rejects retired keys and filters unavailable ordinary grants consistently. | Three regression checks and the full 249-test unit suite passed. Normal browser password/MFA entry restored Platform Staff, its nine QA rows and Add Staff form on the final Docker UI. |

The generic tenant-settings screen is a key/value store. Vendor-defined supported settings, implemented business consumers and reset-to-default semantics are not shipped. Storage-isolation evidence must not be represented as that separate product capability.
